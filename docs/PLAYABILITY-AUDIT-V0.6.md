# Hunger Protocol — 可玩性与美术专项审查 v0.6
**审查性质：** 基于当前 main 分支源码的产品与设计评估；自动化模拟不代表真人试玩和真机性能数据。

## 结论
当前工程底座已经具备页面、存档、战斗、A* 寻路、少量像素绘制和关卡循环，但真正的反向尸潮策略的核心乐趣尚未成立。继续先增加国家、单位数量、货币和 UI 面板，会放大内容体量却难以改善留存。

**最关键的四项：** （1）感染爆发太晚；（2）投放位置无战术约束；（3）关卡缺少有区别的线路与守军事件；（4）单位行为与 UI 反馈不足以产生可验证的决策后果。

## 源码事实与推断

| 级别 | 源码机制 / 发现 | 游戏设计影响 | 应对 |
| --- | --- | --- | --- |
| P0 | `setupMission` 将平民全部设为 `sheltered`，基础感染判定只对 `civilian`；早期以削减 barricade + shelter HP 为主 | 病毒滚雪球是后期奖赏，开局更像打木桩 | 人类起初继续留在庇护所，但警报与资源事件应释放修理员/撤离人群，或提供守卫感染突破路径 |
| P0 | `spawnAtCanvas` 对大部分可走空地允许投放 | 可直接把兵放到目标附近，选择不同街道路线意义很小 | 引入起始污染源、可扩展污染半径与新的渗透点；允许有限范围内的玩家主动布署 |
| P0 | 战斗的玩家操作主体是投兵、全员指挥、全局策略切换和两项技能 | 投放资源不稀缺时，多种打法的结果差别不大 | 创造目标优先级、诱敌/断电/开口、分队进攻等高影响动作；不要强行增加 RTS 微操 |
| P0 | `layoutBuildings` 的中心行列模式相似，各关主要改变人口与守卫数、耐久 | 各关没有独特的路线和可破局结构 | 优先手工制作一个高质量地图：正面路障与侧巷两个攻势入口，真实互动设施 |
| P1 | `walker/runner/brute/spitter` 主要由数值决定差异；spitter 更像远程普攻和粒子 | 缺乏肉眼识别与真实职能区别 | 为单位配置明确的 AI 规则、目标偏好、特效和克制关系 |
| P1 | `nearestTarget` 已考虑寻路和缓存，但人类 AI 基本只巡逻/射击/逃跑；部分条件触发增援 | 对手不能随着玩家策略改变防线，无法形成“破局” | 将人类分为警戒、修复、恐慌、转移、撤离阶段，引入工程兵与可破坏设施 |
| P1 | 感染判定是概率即时转化；`infected` 字段在基础战斗中未形成可见的累积状态机 | 玩家难以理解为什么变成僵尸，也缺少传染过程的倒计时爽感 | 感染阶段条 + 受击短延迟 + 尸变动画 + 局部传染事件 |
| P1 | `meta.energy` 与 `meta.brains` 同时保存并在战斗消耗 | 下一关资源压力与局外进度不清晰，无法给玩家可预测的开局经济 | 彻底区分“本局指挥资源”和“局外永久货币”；迁移旧档 |
| P1 | `finishMission` 只要人数、开门达到阈值即触发；部分失败靠时间或逃走人数 | 结算对过程缺少评价，反复刷关不带来新目标 | 根据失守阶段、撤离人数、剩余尸能、最大连锁感染评分，奖励不同构筑方向 |
| P1 | `resizeWorld` 会重新运行 `layoutBuildings`，而后者随机建筑宽高 | 手机上的横竖屏切换/窗口变化可能改变碰撞与地形，破坏原有动线 | 地图使用稳定种子与标准世界坐标；只变换视口，不重生成地理 |
| P1 | 美术由程序绘制 + 2.5D 建筑高度偏移组成；逻辑 asset catalog 已建立 | 与此前想要的精细等距像素、温暖据点与冷色尸潮仍有明显差距 | 先建立地砖、墙角、窗门、灯光、人物 4-8 向动画的统一尺寸与像素密度 |
| P1 | UI 虽可折叠，但为多个固定定位面板、浮窗和底部卡片 | 战场容易被面板覆盖，操作对象远离拇指常用区域 | 以“状态—意图—反馈”为中心设计单层紧凑移动 HUD |
| P2 | 还没有音频资产或调用；胜利/感染主要是文字、粒子及数值 | 重大突破缺乏声音和动画的情绪峰值 | 设计低频枪响、感染噪声、破门音、战利品音；提供静音与低功耗选项 |
| P2 | `game.js` 仍集中大量逻辑；普通操作触发频繁 DOM 更新 | 未来玩法迭代和性能调参成本高 | 优先抽出 combat / scenario / UI 状态；添加实际 FPS 与交战性能测试 |

## 重做哪一个核心循环？
推荐“诱发恐慌 → 暴露目标 → 诱导感染 → 形成局部尸潮 → 压垮防线 → 追击撤离者”。

**要遵守用户已确认的开局设定：** 初始全部平民在避难所；外部巡逻的人类带枪。不要直接让平民散落街头。可以在剧情事件后打开闸门、派出工程兵、救援车队或转移幸存者，让战场产生新的可感染目标。也可以为武装守卫设计稀有感染破口，但难度更高。

### 新第一关建议：南湾雨夜
- 0–20 秒：玩家自主放置行尸，观察巡逻守卫的视野与前进方向，尝试诱离岗哨。
- 20–50 秒：第一次交手触发警戒；守卫撤回，避难所开闸派遣修理员（并非开局就存在街上的平民）。
- 50–90 秒：玩家可选追击修理队制造尸变，或拆路障创造突破点。第一个成功感染事件在视觉上必须突出。
- 90–180 秒：根据玩家的感染成果/破障进度改变驻防与撤离路线，人类发出撤离警报。
- 180–240 秒：突破、阻止撤离、收割结算。可提前胜利，不让等待填满剩余时间。

这只是目标节奏，不是当前版本已达到的真实计时数据。

### 三关各自的关卡命题
1. **零号街区：** 诱敌与第一次传染。一个明确可见的感染爆发。
2. **公路检查站：** 正门重火力 vs 侧路漏网者；初次真正需要选择路线。
3. **暮色避难所：** 双防线、工程兵修复、撤离倒计时；利用尸种配合完成突围。

## 资源与长期成长重构
- **战内：** 尸能（自动恢复/感染奖励）、战术能量（通过战场事件获得）、容量（尸群总量限制）。
- **战外：** 生物质（持久研究）、突变标本（关卡目标奖励）、器官（少数改变玩法的构筑）。
- **禁止：** 同一资源同时承担可再生战斗燃料、长期研究和技能消耗，又不给稳定的开局状态。
- **器官原则：** 首批只做 4–6 件真正改变行为的器官；要能组成至少两种差异明显的打法。

## 视觉目标与素材标准
- 目标不是简单降低分辨率或给场景加像素噪点，而是面向“等距像素的末世居民区”：可信的建筑结构、层叠屋顶、废旧车、地面使用痕迹、路灯与室内暖光对比。
- 按 2:1 等距投影或经过验证的 2.5D 统一基准；每件资源保留地面接触点、碰撞矩形、前后层级、资源 ID。
- 先集中制作一张 **可玩的美术样板关卡**，不应先随机生成大量低辨识度建筑。
- UI 不建议再继续叠 CSS。先完成视觉语言方案：图标体系、8px 基础间距、统一信息级别、低饱和配色、简约操作栏、一次只突出一个任务。
- 概念图是视觉目标，而不是可直接使用的建筑贴图资源包。真实可玩关卡需要拆成可复用 tile/sprite atlas。

## 分阶段整改与验收

| 阶段 | 重点 | 验收门槛 |
| --- | --- | --- |
| P0 菜单与新手 | 有档默认突出继续；减少不必要的操作；独立新游戏二次确认 | 有档首页默认主按钮为继续；新档第一屏只显示行尸、尸能和一句任务 |
| P1 核心爽点（优先） | 首次感染时机、感染状态可视化、人类防线的事件响应、部署区域约束 | 新玩家首局在合理时间内主动引发一次感染爆发；出现至少两种会影响结果的决策 |
| P2 战术内容 | 一张两进攻路线地图；守卫/工程兵反制；尸种职能与克制 | 同一关至少两条有效通关策略且能明确复盘 |
| P3 视觉纵切 | 美术 tilemap、复用资产集、角色动画、关键音画反馈、HUD 版式 | 演示关卡整体接近此前认可的等距像素末世概念图；场景可辨读、操控不受遮挡 |
| P4 成长平衡 | 战内/局外经济拆分、器官流派、挑战目标与结算 | 感染流和暴食流能够产生不同战局路径；重复挑战有自主目标 |
| P5 稳定性与数据 | FPS、日志、真实浏览器、压力测试、手机触控 | 无高频卡角/误触；有实际设备测得的性能及首局完成数据 |

### 需要数据验证的指标（不是现有实测）
- **首次有意义操作时间**：希望 10 秒内可以理解并执行第一步。
- **首次感染爽点**：目标在 60–90 秒左右可以触发一次主动制造的感染事件。
- **有效决策**：每局出现至少两次“选不同策略导致结果不同”的可验证机会。
- **关卡节奏**：首关 3–4 分钟，后续标准关 4–6 分钟；应可提前完成。
- **可玩性测试**：至少 5–10 名没有接触过项目的人实际试玩，记录首局成功率、卡住位置、无操作时间和重玩意愿。
- **真实性能**：中端手机 30–60 FPS 区间目标需通过真机测量，不能以 jsdom 通过代替。
