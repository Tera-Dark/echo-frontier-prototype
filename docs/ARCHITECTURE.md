# 工程架构与手机迁移路线

## 基本原则
**网页先可玩、可靠、易测试；原生 App 复用同一份 Web 产物。** 保留 Canvas，不为“架构先进”进行一次性重写，避免破坏战斗体验与旧存档。

## 模块及职责

| 路径 | 当前角色 | 下一步 |
| --- | --- | --- |
| src/core/storage.js | 存档键、兼容加载、值类型/范围检查、设置读写 | 将来扩展导出/备份接口 |
| src/core/clock.js | 固定时间步与后台卡帧保护 | 加入压力数据采集 |
| game.js | 地图数据、AI、战斗、镜头、Canvas、DOM 混合 | **待拆解的主要技术债** |
| index.html / style.css | 全屏 HUD、战场和管理抽屉 | 更严格的触控及无障碍验收 |
| assets / manifest / sw.js | Web/PWA 图标、离线资源 | 版本化资源、真机离线验收 |
| scripts/build.cjs / dist | 无框架、仅游戏资源的发布物 | 加入正式构建版本与资源清单 |
| tests/core.cjs / tests/smoke.cjs | 存档、时钟、DOM/Canvas 模拟交互 | 结算与关卡状态回归 |
| capacitor.config.json | 未来 Android/iOS WebView 容器配置 | 仅在网页版成熟后添加原生工程 |

## 边界规则
- 游戏核心逻辑不直接依赖 Android/iOS SDK；后续通过独立平台服务层接入触觉、状态栏、生命周期、导出等能力。
- 保留旧 localStorage 键。读档必须经过标准化校验，不能把未验证的 JSON 合并进运行状态。
- Web/移动两端都由 dist/ 打包。原生壳只负责设备级功能，不能持有另一套游戏规则。
- 游戏模拟使用固定时间步；渲染帧率与模拟速度解耦。切后台暂停以避免超大时间跳变。
- 地图世界坐标、镜头坐标与屏幕触摸坐标必须清晰隔离。
- 高优先级交互和状态机每修一次就增补一次测试，禁止再用“语法检查通过”冒充可玩性验收。

## 分阶段重构

**P0（网页可靠性）：** 回归验证胜败结算、地区切换、重复奖励、加载损坏存档、战场投放与镜头触控。修复无法继续游戏的状态跳转。

**P1（性能/操控）：** 寻路热点分析、目标选择缓存、单位上限压力测试、手机 UI 命中区域与真机触控。加入 FPS、活动实体和 AI 耗时观测选项。

**P1（继续模块化）：** 逐步把 game.js 拆为数据、simulation、render、ui。每次只提取一个不变职责，确保现有测试始终通过，避免一次 900+ 行大爆炸改动。

**P2（扩充玩法）：** 关卡独特机制、尸群职业差异、幸存者的反制行为、主动技能与器官构筑、难度平衡。

**P3（移动 App）：** 安装兼容版本的 Capacitor，创建 Android 工程，处理物理返回键、状态栏、离线资源、退出与升级存档、性能/隐私/签名等事项。当前仓库尚不包含 APK 或原生编译产物。

## 已知边界
目前存档离线、本地单人、程序化美术；没有联机、云同步和平台账户。jsdom + Canvas 模拟能检查按钮和数据流，但不能证明浏览器真实 FPS、GPU 消耗、离线网络缓存或手机 App 表现。
