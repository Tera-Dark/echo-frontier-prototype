# 寻路系统 v0.6：移动、目标选择与卡角恢复

## 为什么原来会卡住
旧实现采用较稀疏的网格，而路径平滑、寻路碰撞和实体最终移动用的是不同的避障半径。目标点还可能被放在建筑内，导致不断清空路径与撞墙重算。

## 现在的规则
1. **统一几何**：`src/core/navigation.js` 构建基于当前建筑与未破坏路障的通行栅格；格子和线段检测都使用一致的安全余量。
2. **禁止斜切墙角**：A* 对角行走必须同时通过相邻的两个正交格子。
3. **平滑后验证**：路径节点删减时必须经过完整的线段碰撞检测。
4. **目标边缘接近**：攻击路障、避难所入口时选择建筑外侧可到达的候选攻击点，不能直接朝碰撞体中心移动。
5. **滑墙与恢复**：被碰撞阻挡后先尝试沿空闲轴移动；持续无法接近目标会清理旧路径并临时选择附近可通行节点。即使在墙角来回滑动也会触发进度检查。
6. **距离不是一切**：自动猎食评估最近的若干候选目标，比较可达的路线长度，拒绝隔墙不可达者。
7. **手动指挥**：队形槽位需要投影到可通行区域；无法通过现有道路到达时明确拒绝指令。
8. **减少开销**：每个单位缓存目标一小段时间，同地图共享限定大小的 A* 网格路径缓存；路障被拆除后重建导航并自动清理缓存。

## 验收测试
- `node tests/navigation.cjs`：几何一致、建筑绕行、路线平滑、可到达攻击点、完全阻隔检测、共享缓存、场景资产注册表。
- `node tests/smoke.cjs`：正常浏览器逻辑模拟中的按钮、控制、A*、路障、战斗结算及可折叠 HUD。
- UI 真机仍需测试：大量单位同时寻找人类、窄巷组队、50/100+ 单位压力及长时间运行性能。

## 注意
这是二维平面世界的地面寻路，不是完整的局部群体避碰/RVO。未来若改成真正 2:1 等距世界，需要在统一世界坐标系中迁移投影和通行关系，不能只替换地图画法。
